# RUNBOOK — как правильно снимать и мерить

Отвечает на два вопроса: **откуда** снимать (вантаж) и **как** гонять серию.
Дизайн и критерии приёмки — в `README.md`.

## 1. Выбор вантажа (важнее, чем кажется)

Цензор (ТСПУ) сидит на пути **рядом с клиентом, внутри страны**. Relay —
заграничный VPS, за международным каналом.

| признак                         | relay-захват | клиентский захват |
|---------------------------------|--------------|-------------------|
| размеры записей, направление, последовательности | честно | честно |
| **тайминг / периодичность chaff** | **занижены** (джиттер канала размазывает каденцию) | **честно** (точка цензора) |

**Правило:** первичный вантаж — **клиентский** (этот Mac / iOS-устройство).
relay-захват допустим только для признаков размеров и для L3. Все классы
одной серии снимаются с ОДНОГО вантажа — иначе сравниваешь путь, а не Construct.

**Какой клиент:** наш нативный отпечаток — iOS (Network.framework). Захват на
Mac-клиенте меряет rustls-путь (другая паковка TLS-записей), НЕ iOS.
- Золотой стандарт (реальная iOS-форма): **iOS-устройство через `rvictl`**.
- Быстрый прокси: **desktop-клиент на Mac** — с оговоркой, что это rustls-путь.

## 2. Нужен ли одновременный захват сервер+клиент?

- **L2 (сессия vs обычный клиент): НЕТ.** Один клиентский вантаж на все классы.
- **L3 (кто с кем): да, оба клиента разом** — но один relay-`tcpdump` видит
  обоих одновременно, это проще двух клиентских захватов.
- **Разовая калибровка пути:** снять одну сессию с обоих концов сразу, чтобы
  измерить, насколько relay занижает тайминг. Один раз, не на каждую сессию.

## 3. Серия L2 (первый настоящий вердикт)

Цель: **≥25–30 визитов на класс** (при меньшем N гибкая модель недостоверна —
измерено self-test'ом). Классы: `cover-real`, `veil-idle`, `veil-active`.
Варьируй время суток/сеть между визитами.

### 3a. cover-real (эталон «обычный веб-клиент того же origin»)
Браузер без тикета Construct → relay уводит на honest-front cover → на проводе
это настоящий трафик сайта того же origin.
```bash
# терминал 1 — клиентский захват (пример для desktop/Playwright на Mac, en0):
capture/capture_local.sh cover-real 60 195.133.44.113 en0 443
# терминал 2 — сразу же реальный визит браузера на тот же origin:
.venv/bin/python capture/baseline_browser.py https://api.divany-kresla.uk --visits 1 --dwell 40
# повторить ~25 раз (можно --visits 1 в цикле с паузами)
```

### 3b. veil-idle / veil-active
```bash
capture/capture_local.sh veil-idle   60 195.133.44.113 en0 443   # VEIL поднят, не пишем
capture/capture_local.sh veil-active 60 195.133.44.113 en0 443   # активная переписка
```
Для iOS: `rvictl -s <UDID>` → iface `rvi0`; в конце `rvictl -x <UDID>`.

### 3c. извлечь → признаки → классификатор
```bash
for f in samples/*.pcap; do
  lbl=$(basename "$f" | sed 's/__.*//')
  .venv/bin/python extract/pcap_to_records.py "$f" --server-port 443 --tag "$lbl" \
     -o "samples/$(basename "${f%.pcap}").csv"
done
.venv/bin/python features/build_features.py samples/*.csv -o report/feat_l2.csv
.venv/bin/python classify/l2_classifier.py report/feat_l2.csv \
     --positive veil --negative cover-real --n-perm 500 -o report/l2.json
```
**Вердикт L2:** разделение реально, только если p-value мало у ОБЕИХ моделей.
p велик (>0.05) → неотличимо при данном N (это цель). Всегда читай `top_features`.

## 4. Серия L3 (кто с кем)

Два устройства переписываются друг с другом через relay; один relay-захват
видит обе сессии. Метки — `pair-<id>-A` и `pair-<id>-B`. Нужно ≥6–8 пар.
```bash
# на relay (divany :443 напрямую; nearsky — port 8443 за nginx):
capture/capture.sh divany pair-01-A 120     # запускать под каждую сессию/устройство
# затем расставить метки A/B по устройствам и:
.venv/bin/python extract/pcap_to_records.py samples/pair-*.pcap --server-port 443 ...
.venv/bin/python classify/l3_correlation.py samples/pair-*.csv
```
**Вердикт L3:** matching advantage над случайным ≈ 0 → связать нельзя (цель).

## 5. Порты и хосты (памятка)
- **divany** `195.133.44.113` `~/.ssh/secondvps` — relay напрямую на **:443**.
- **nearsky** `178.236.240.21` `~/.ssh/aeza` — nginx :443 → relay **:8443**
  (relay-захват на nearsky снимай с `--server-port 8443`; см. память деплоя).
- Клиентский захват всегда `port 443` (клиент видит внешний порт origin).

## 6. Типичные ошибки
- смешать вантажи (veil клиентский, cover relay) → меряешь путь, не Construct;
- N<25 → GBM недостоверен (permutation p скачет);
- забыть `--server-port 8443` на nearsky relay → направления перепутаны;
- считать высокий AUC на synthetic победой — это тест СТЕНДА (`selftest.sh`),
  не VEIL.
