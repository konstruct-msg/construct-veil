# shape-lab — измерительный стенд неотличимости VEIL

Стенд играет роль **цензора-классификатора**. Он не проверяет «похоже ли»,
он пытается **отличить** сессию Construct от обычного веб-клиента того же
origin (L2) и **связать** двух собеседников (L3). Если не может — это
доказательство. Если может — feature importance говорит, *что течёт*.

Планка — из `construct-transport-spec.md` (M1/M2) и `construct-transport-review.md`
(§1, §7, §14). Мерим **ROC-AUC при заранее зафиксированной низкой FPR**, а не
«KS p>0.05» (ревью §14 прямо это запрещает как достаточный критерий).

## Модель наблюдателя (что цензор видит на проводе)

ТСПУ / national on-path. Видит: размеры TLS-записей, тайминг, направление,
IP/порт, SNI, длительность и число коннектов. **Не** видит plaintext (TLS 1.3
не ломается — spec §1). Всё пространство признаков ниже выводится ТОЛЬКО из
этого. Расшифровка не нужна и не делается — цензор её тоже не делает.

## Классы сессий (метки захвата)

| метка        | что это                                                        |
|--------------|----------------------------------------------------------------|
| `cover-real` | настоящий браузер (Playwright) грузит реальный сайт того же origin — эталон «обычный веб-клиент» из spec §1.2 |
| `veil-idle`  | VEIL поднят, переписки нет (тикает chaff/keepalive)            |
| `veil-active`| активная переписка через VEIL                                  |
| `pair-*`     | пары `veil-active` с двух клиентов с разметкой «кто с кем» (для L3) |

Требование методологии (ревью §14): N сессий на класс (не одна), варьировать
время/устройство/сеть; сплит train/test **по сессии**, не по записи; FPR
фиксируем ДО эксперимента (по умолчанию 1%).

## Пайплайн (4 ступени)

1. **capture/** — `tcpdump -B` помечает pcap по классам; `baseline_browser.py`
   гонит Playwright по реальному origin. **Вантаж — клиентский** (точка цензора;
   relay-захват занижает тайминг/периодичность). Подробно: `RUNBOOK.md`.
2. **extract/** — `pcap_to_records.py`: tshark → per-session CSV записей
   (`ts, dir, tls_record_len, content_type`). Единственный проводной парсер.
3. **features/** — `build_features.py`: CSV → вектор признаков на сессию +
   кросс-поток для пар.
4. **classify/** — `l2_classifier.py` (veil vs cover-real) и
   `l3_correlation.py` (пары). Отчёты в `report/`.

## Пространство признаков

**Объём/сессия:** байты↑/↓, отношение, длительность, число записей, число коннектов.
**Распределения (ядро M1):** гистограммы размеров записей ↑/↓; гистограммы межзаписных интервалов ↑/↓.
**Последовательности (§14):** последовательность (направление, корзина размера) — n-граммы; структура пачек (burst) и межпачечные паузы.
**Периодичность (детектор chaff):** автокорреляция/FFT ряда отправок — ровный chaff/keepalive засветится здесь (риск §1/§7).
**Кросс-поток (L3/M2):** сдвиговая кросс-корреляция и взаимная информация между ↑-событиями A и ↓-событиями B по лагам; «преимущество сопоставления» пар над случайным.

## Классификаторы (по нарастающей мощности — ревью требует набор, не один)

1. пороги по одному признаку (объём, длительность) — самый дешёвый цензор;
2. логрегрессия на распределениях;
3. градиентный бустинг на всём наборе;
4. (при нужде) sequence-модель по (dir, bucket).

## Критерии приёмки (гейты)

- **L2 (M1):** лучший классификатор даёт **ROC-AUC ≈ 0.5** и recall@FPR=1% ≈ FPR
  на `veil-{idle,active}` против `cover-real`. KS по-признаково — только диагностика.
- **L3 (M2):** «преимущество сопоставления» пар над случайным ≈ 0; взаимная
  информация A↑/B↓ на уровне шума.
- **Negative control (обязателен):** два захвата ОДНОГО класса → AUC≈0.5. Иначе
  пайплайн ловит фантом (артефакт пути/времени), а не свойство Construct.
- **Feature importances** публикуются всегда — это карта того, что чинить в шейпере.

## Правило интерпретации (валидировано self-test'ом 2026-09-19)

`selftest.sh` гоняет стенд на синтетике и подтверждает, что машинерия:
- **ловит** заведомо разные классы: veil vs cover → ROC-AUC=1.0, permutation **p=0.000**;
- **ловит** связность пар: correlated → matching advantage **+0.857**; independent → **−0.018** (шум);
- **предупреждает о малом N**: negative control (два сэмпла одного класса, N=12/класс)
  дал GBM ROC-AUC=0.844 при **p=0.045** — на самой границе значимости. Это не баг
  стенда, а его честный сигнал: **при N=12 гибкая модель находит фантом**.

Отсюда — обязательные правила для реальных захватов:

1. **Вердикт по permutation p-value, не по «сырому» AUC.** Разделение реально,
   только если p значимо мало у ОБЕИХ моделей (logreg и GBM), а не у одной.
2. **Минимум N.** Цельтесь в **≥25–30 визитов на класс**, чтобы null-floor
   опустился и neg-control стал уверенно не значим (p>0.2 у всех моделей).
   При N=12 GBM недостоверен — это измерено.
3. **Сопоставимость пути.** Все классы снимаются на одном relay тем же tcpdump
   (`cover-real` = браузер без тикета → honest-front cover того же origin).
4. **Feature importances** читаются всегда — даже при «pass» они показывают
   ближайший к утечке признак (кандидаты по гипотезе: `duration`, `period_up_*`,
   `n_streams` — долгий коннект с ровным chaff против коротких всплесков браузера).

## Как гонять

`./selftest.sh` — регрессия самого стенда (без сети). Реальный прогон
(вантаж, хореография, число сессий, порты) — по шагам в **`RUNBOOK.md`**.
